Fluxos

Como funciona

→
Atendimento Completo com Escalação
1
Cliente envia mensagem no Telegram → bot.py recebe e verifica se há sessão humana ativa
2
agent.py monta prompt com system prompt + golden examples + learnings do dia + histórico (20 msgs)
3
Claude decide: responder direto OU chamar tool (buscar_produtos / consultar_produto / sugestoes_combinadas)
4
Se detecta [ESCALAR_HUMANO]: bot resume a conversa, notifica grupo de suporte com contexto completo
5
Atendente humano responde via >USER_ID no grupo; /bot USER_ID devolve o controle ao KushBot
Módulos

Componentes principais

agent.py — Cérebro
Orquestra o Claude com tool use. Decide quando buscar catálogo, consultar Wbuy ao vivo, sugerir cross-sell ou escalar pro humano. Nunca inventa preço.
4 tools: buscar_produtos, consultar_produto, sugestoes_combinadas, consultar_preco_historico
Flag [ESCALAR_HUMANO] para detecção de casos críticos
Injeção dinâmica de golden examples + learnings no system prompt
Sumarização de conversa para briefing do atendente humano
await agent.chat(user_id=42, message='tem o Mighty Plus em estoque?')
→ consultar_produto('Mighty Plus') → Wbuy ao vivo → 'Sim! Mighty Plus R$2.890 — 3 unidades em estoque. PIX cai na hora 🔥'
conversations.py — Memória
Persistência em SQLite com threading-safe. Guarda cada turno (incluindo blocos tool_use/tool_result) para sobreviver a reinicializações do bot.
Tabelas: conversations, messages, escalations
MAX_HISTORY=20 turnos no contexto vivo, histórico completo em disco
Controle de sessão humana ativa por user_id
messages_since(ts) para pipeline de learnings
conversations.get_history(user_id=42)
→ 20 últimas mensagens do SQLite, prontas para injetar no prompt do Claude
learnings.py — Evolução
Pipeline diário que usa Claude Haiku para extrair padrões das conversas das últimas 24h e gerar learnings.md injetado no bot do dia seguinte.
Perguntas frequentes com resposta-modelo
Gírias e expressões novas do público vape
Objeções tratadas com sucesso para replicar
Produtos perguntados que não estão no catálogo
python learnings.py --since 7d
→ 47 conversas analisadas → learnings.md atualizado → bot amanhã entra sabendo das trends da semana
catalog.py + wbuy_client.py — Catálogo
Sincronização periódica com a Wbuy (a cada 3h) e busca fuzzy local. Para preço/estoque definitivo, consulta a Wbuy ao vivo via tool.
Normalização de múltiplos schemas da API Wbuy
Busca fuzzy sem acento, case-insensitive
5 esquemas de auth: bearer, bearer_basic, header, basic, query
Background sync loop sem bloquear o bot
search_local('vape conveccao até 1000')
→ [Mighty Plus, Venty, XQ2, Starry 4.0] com preço, marca, categoria e link da loja
co_purchases.py — Cross-sell Real
Analisa exports de pedidos reais para descobrir quais produtos são comprados juntos. Alimenta a tool sugestoes_combinadas — zero chute.
Ingesta CSV ou JSON de pedidos exportados da Wbuy
Algoritmo de co-ocorrência com frequência mínima configurável
Top 5 sugestões por produto
Se lista vazia, bot não força cross-sell
python co_purchases.py # processa data/orders/
→ co_purchases.json gerado: 'Solo 3 → [Adaptador de Bong, Dichavador Space Case, Grinder SLX]'
golden_examples.py — Tom e Estilo
Carrega atendimentos reais bem-sucedidos de golden_conversations/*.md e injeta como few-shot no system prompt. Bruno curadora, bot aprende.
Prioridade por tag [priority=high]
Máximo 6 exemplos no contexto (custo controlado)
Suporte a tags para categorização (iniciante, premium, objeção)
Hot-reload: basta reiniciar o bot após editar os arquivos
render_examples_block()
→ Bloco markdown com até 6 atendimentos reais injetado no system prompt antes de cada sessão

Filosofia

O que guia cada decisão

⭐
"Um bot que nunca chuta — cada recomendação vem do catálogo real, cada preço vem da API ao vivo, cada sugestão vem de comportamento real de compra."
PRINCÍPIO 01
Honestidade sobre incerteza: se não sabe o preço atual, diz que vai verificar — nunca inventa
PRINCÍPIO 02
Contexto é memória: o bot lembra do cliente entre sessões, o atendente humano herda o contexto completo na escalação
PRINCÍPIO 03
Isolamento entre lojas: cada loja é um negócio diferente — o bot da Elite Vape jamais fala de pedido feito na Aldeia Vape
Filtro de feature
Antes de implementar qualquer feature, perguntar: isso elimina chute ou elimina atrito para o cliente? Se não fizer nenhum dos dois, está fora do escopo.
