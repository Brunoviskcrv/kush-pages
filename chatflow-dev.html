Fluxos

Como funciona

→
Atendimento via Widget
1
Visitante abre o widget embarcado no site do cliente
2
Widget conecta ao namespace /widget do Socket.io e cria conversa com status 'bot'
3
Mensagem chega ao backend e é persistida em messages + emitida ao namespace /dashboard
4
Operador responsável pelo canal recebe em tempo real e responde pelo dashboard React
5
Ao encerrar, Claude gera resumo automático salvo em ai_summaries
→
Recebimento de E-mail
1
E-mail chega no canal configurado (Cloudflare Email Worker ou Mailgun webhook)
2
POST /api/email/inbound — backend normaliza remetente, assunto e corpo
3
receiveEmail() identifica canal pelo endereço 'to', cria ou atualiza conversa com source='email'
4
Evento Socket.io emitido ao dashboard — operador do canal é notificado
5
Operador responde via POST /api/email/reply — Brevo envia o e-mail ao visitante
→
Atendimento via Telegram
1
Admin conecta canal Telegram (número + session GramJS) pelo painel
2
Backend escuta mensagens recebidas e vincula ao telegram_channel_id na conversa
3
Conversa aparece na fila do operador atribuído ao canal
4
Operador responde pelo dashboard — backend encaminha via API do Telegram
5
Mídias (áudio OGG, imagens, vídeos) são salvas em public/uploads/ e repassadas
Módulos

Componentes principais

Widget Embed
Bundle IIFE gerado pelo Vite que pode ser inserido em qualquer site externo via tag <script> ou API JS. Conecta ao namespace /widget do Socket.io e abre uma conversa com status 'bot'.
Embed com uma linha de HTML
Mount programático via window.ChatFlow.mount()
Cor primária configurável por organização
Reconexão automática em queda de rede
window.ChatFlow.mount({ serverUrl: 'https://api.exemplo.com', organizationId: 'uuid', primaryColor: '#4f46e5' })
✓ widget montado — socket /widget conectado — conversa criada
Motor de E-mail
Recebe e-mails inbound via Cloudflare Email Worker (JSON) ou Mailgun webhook (multipart), cria/atualiza conversas com source='email' e envia respostas transacionais via Brevo.
Suporte a Cloudflare Email Routing e Mailgun
Parsing de remetente, assunto e corpo limpo
Threading por email_message_id
Repasse de anexos base64 para disco
POST /api/email/inbound { from, to, subject, body }
✓ conversa email criada (id: uuid) — operador notificado via socket
Integração Telegram
Conecta canais Telegram via GramJS (MTProto nativo). Cada canal tem número de telefone e session string próprios. Mensagens e mídias (áudio OGG, imagens) são unificadas na mesma fila do dashboard.
Múltiplos canais Telegram por instalação
Envio e recebimento de voz (OGG/Opus)
Reconexão automática de sessão
Status do canal: disconnected / connecting / connected / 2fa_needed
npm run db:migrate:telegram && node src/config/create-operators.js
✓ telegram_channels criada — operadores vinculados ao canal
Resumos IA (Claude)
Ao encerrar uma conversa, o backend chama a API do Anthropic Claude para gerar um resumo estruturado do atendimento, persistido em ai_summaries e exibido no dashboard.
Resumo automático no fechamento da conversa
Histórico de resumos por conversa
Acessível via GET /api/chats/:id/summary
Zero configuração extra — usa ANTHROPIC_API_KEY do .env
PATCH /api/chats/conv-uuid/status { status: 'closed' }
✓ Claude gerou resumo — salvo em ai_summaries — conversa arquivada
Quick Replies com Auto-save
Sistema de mensagens rápidas pessoais e globais. O endpoint /track monitora frequência de envio e salva automaticamente mensagens enviadas 3+ vezes como quick reply, sem intervenção do operador.
Mensagens pessoais e globais (admin) separadas
Ordenação por use_count decrescente
Auto-save silencioso após 3 envios da mesma mensagem
Deduplicação por conteúdo com ON CONFLICT
POST /api/quick-replies/track { content: 'Olá! Como posso ajudar?' }
✓ count=3 atingido — salvo em quick_replies automaticamente
Gestão de Operadores e Canais
CRUD completo de operadores com controle de roles (admin/operator), atribuição de operadores a canais específicos (widget, email, telegram) e bloqueio de auto-desativação.
Criação, edição e ativação/desativação de operadores
Atribuição de operador primário por canal
Filtro de conversas por canal atribuído ao operador logado
Modo emergência: operador vê todas as conversas independente de canal
POST /api/operators/channels { operator_id, channel_id, channel_type: 'telegram', is_primary: true }
✓ channel_operators inserido — operador verá conversas do canal Telegram

Próximos Passos

Priorizado por urgência

Alta Prioridade
Bot LLM na fila
Antes de acionar operador humano, Claude responde automaticamente usando contexto da conversa — reduz carga de atendimento em conversas simples.
Docker Compose
Arquivo único para subir backend + dashboard + widget + PostgreSQL com um único 'docker compose up' — elimina setup manual de banco.
Notificações push
Alertas de nova conversa por e-mail ou push browser para operadores offline — evita conversas sem resposta acumulando na fila.
Próximas Entregas
Transferência de conversa
Operador pode reassinar uma conversa em curso para outro colega sem perder o histórico — fundamental para times com especialidades distintas.
OAuth Google
Login de operadores via conta Google — elimina gestão de senha e facilita onboarding de novos atendentes.
Relatórios com filtro de período
A rota /api/reports/stats já tem o scaffold; falta concluir o cálculo de intervalo customizado e conectar ao frontend.
Fundação Técnica
Testes automatizados
O projeto não tem suíte de testes. Adicionar Vitest para unitários e Supertest para rotas REST garante segurança nas evoluções futuras.
Isolamento multi-tenant real
Hoje organizations existe apenas no schema legado. Separar dados por organização com Row-Level Security no PostgreSQL é pré-requisito para SaaS.
CI/CD pipeline
GitHub Actions rodando lint + testes + build automático a cada push — pré-requisito para deploys confiáveis em produção.
Filosofia

O que guia cada decisão

⭐
"Qualquer canal onde o cliente já está — uma fila única onde o operador já trabalha"
PRINCÍPIO 01
Zero fricção para o visitante: abrir o widget ou enviar um e-mail já é suficiente para iniciar um atendimento
PRINCÍPIO 02
Operadores veem apenas o que é relevante para eles — filtro por canal elimina ruído sem esconder emergências
PRINCÍPIO 03
IA como copiloto, nunca como barreira — Claude enriquece (resumos, automação futura) sem substituir o julgamento humano
Filtro de feature
A feature entra se reduz tempo de resposta ao visitante OU reduz esforço cognitivo do operador — funcionalidades puramente administrativas ficam para depois
