AI Router (9 Providers)
Camada de roteamento inteligente que separa tarefas leves (pesquisa, perguntas, resumos) de pesadas (geração de código). Fallback automático em runtime com health check no startup.
light(): Groq → Together → Ollama → Gemini → DeepSeek → GPT-4 → Claude Haiku
heavy(): usa DEFAULT_AI_PROVIDER (Claude Sonnet por padrão)
Fallback automático se provider responde 429 ou timeout
Health check no startup + background re-check de providers offline

Sandbox Executor
Ambiente de execução isolado em /tmp com timeout configurável. Roda Python e Node.js. É o único teste formal do sistema — todo projeto gerado passa pelo sandbox antes de ser publicado.
Execução em diretório temporário isolado
Timeout de 30s (configurável via SANDBOX_TIMEOUT)
Remove variáveis de ambiente sensíveis antes da execução
Captura stdout/stderr (limite 4000 chars) para contexto de correção
Limitação conhecida: não abre browser — HTML precisa de DOMContentLoaded explícito

Próximos Passos

Priorizado por urgência

Alta Prioridade
Timeout por step de pipeline
asyncio.wait_for em cada chamada de provider com tempo proporcional ao trabalho. Hoje um step travado de 4min consome todo o budget de 5min do pipeline.
test_coherence — campos contextuais obrigatórios
Rejeitar payload de avaliação que não contenha found_features E (missing_features OU critical_issues). Score sem contexto = avaliação inválida = retry.
Prompt HTML — addEventListener dentro de DOMContentLoaded
Listeners fora do DOMContentLoaded causam TypeError silencioso que paralisa o script. Sandbox não detecta — só o browser. Exigir no prompt de geração e melhoria.
Próximas Entregas
Briefing persistence no repo gerado
Salvar BRIEFING.md (ou .kush/briefing.json) no GitHub do projeto ao concluir /aprovar. Cada /melhorar futuro lê o briefing e sugere completar gaps antes de adicionar features novas.
Validação de disponibilidade no startup
Pingar cada provider registrado com chamada leve. Montar fila de fallback dinamicamente com base no resultado — não em ordem hardcoded.
Coleta silenciosa de performance
Adicionar campos na tabela Tasks: agent_id, correction_attempts, coherence_score, sandbox_passed_first_try. Base para governança de agentes na Fase 3.
Fundação Técnica
Checkpoint de pipeline
Salvar estado intermediário (research + questions + summary) entre steps. Se generate_project falhar após o usuário aprovar, retomar sem re-perguntar.
Relatório semanal de performance por agente
Agregar pass rate, correction rate e coherence avg por agente. Enviar para Bruno via Telegram. Acionar após 4 semanas de dados em produção.
SAFETY Sprint 2-3
Security scan, pip audit, lint e pre-deploy checks antes de qualquer publicação no GitHub. Pré-requisito para /melhorar em projetos de produção da equipe.
Filosofia

O que guia cada decisão

⭐
"Este projeto existe para evoluir — 1% ao dia é o mínimo, o máximo não existe"
PRINCÍPIO 01
Clarificar antes de construir: entender profundamente o que deve ser feito antes de gerar uma linha de código
PRINCÍPIO 02
Autonomia com transparência: agentes autônomos só funcionam quando o usuário sabe exatamente o que vai acontecer
PRINCÍPIO 03
Aprender de qualquer fonte: código externo é livro de receitas, não manual de instruções — expande o que existe, nunca limita
Filtro de feature
Para cada ideia, perguntar: isso expande o que já existe? Se contradiz a filosofia de crescimento contínuo ou tenta reduzir escopo prematuramente — rejeitar e documentar o motivo.
