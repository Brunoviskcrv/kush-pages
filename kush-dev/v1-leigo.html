Fluxos

Como funciona

→
/criar — Da Ideia ao Projeto Publicado
1
Um agente de pesquisa analisa sua ideia usando uma IA mais leve: quais ferramentas usar, como estruturar, o que evitar
2
Outro agente faz perguntas inteligentes com base nessa pesquisa; você responde ou pula
3
Um terceiro agente monta um plano detalhado do projeto; você confirma com /aprovar antes de qualquer código ser gerado
4
A IA gera todos os arquivos do projeto de uma vez, organizados e prontos
5
O código roda num ambiente de teste isolado por até 30 segundos; se falhar, o bot tenta corrigir sozinho até 3 vezes; se passar, publica no GitHub e te manda o link
→
/melhorar — Ajuste Preciso via Revisão
1
O bot lê até 30 arquivos do seu projeto no GitHub
2
Antes de mexer em qualquer coisa, ele identifica as dependências fixas do projeto e garante que nada vai quebrar por causa delas
3
Verifica se há arquivos protegidos e, se o alvo for o próprio Kush-Dev, ativa um modo extra-cauteloso
4
O agente planeja exatamente quais arquivos precisam mudar e só toca neles, deixando o resto intacto
5
Testa as mudanças no ambiente isolado, abre uma proposta de alteração (como um rascunho para você revisar) e te manda o link

Próximos Passos

Priorizado por urgência

Alta Prioridade
Verificar se o código faz o que foi pedido
Depois do teste isolado, uma IA compara o que foi combinado no início com o que o código realmente faz. Se estiver faltando algo importante, o bot não publica — volta a corrigir com informação sobre o que está faltando.
Salvar o combinado junto com o projeto
Ao final do /aprovar, salvar um arquivo com o resumo do que foi acordado dentro do próprio projeto no GitHub. Quando você pedir melhorias no futuro, o bot lê esse arquivo e sugere completar o que falta antes de adicionar coisas novas.
Tempo limite por etapa, não pelo processo todo
Em vez de um único temporizador de 5 minutos para tudo, cada etapa tem seu próprio limite (pesquisa 30s, geração 3min, correção 2min). Assim, uma etapa travada não compromete o tempo das outras.
Próximas Entregas
Verificar serviços de IA ao iniciar
Ao ligar o bot, ele faz um teste rápido em cada serviço de IA disponível. A ordem de tentativas é montada com base no que está funcionando de verdade naquele momento, não numa lista fixa.
Registrar desempenho silenciosamente
Guardar, para cada tarefa: qual agente foi usado, quantas correções foram necessárias, se o código passou na verificação de propósito e se passou no teste na primeira tentativa. Essa base vai alimentar relatórios e melhorias futuras.
Salvar progresso entre etapas
Guardar o resultado de cada etapa enquanto o processo roda. Se algo falhar depois que você já aprovou o plano, o bot retoma de onde parou — sem refazer pesquisa e perguntas do zero.
Fundação Técnica
Instrução obrigatória sobre ordem de carregamento no HTML
Exigir que todo código que interage com a página espere ela carregar completamente antes de rodar. Sem essa instrução, partes do código podem travar silenciosamente — o teste isolado não pega, mas o navegador quebra.
Verificação de qualidade da avaliação de coerência
Rejeitar qualquer avaliação que não informe o que foi encontrado E o que está faltando ou com problema. Uma nota sem contexto não serve para decidir se publica — o bot refaz a avaliação, nunca usa dados incompletos para publicar.
Segurança — Revisão visual e desfazer alterações
Antes de abrir a proposta de alteração, mostrar no Telegram exatamente o que vai mudar, de forma legível. Criar o comando /rejeitar para fechar a proposta e registrar o motivo, ajudando o bot a aprender com o feedback.
Filosofia

O que guia cada decisão

⭐
"Este projeto existe para crescer — não para ser entregue, vendido ou apresentado. Melhorar 1% por dia é o mínimo. O máximo não existe."
PRINCÍPIO 01
Entender antes de construir — mergulhar fundo no problema antes de escrever qualquer coisa
PRINCÍPIO 02
Agir sozinho, mas com transparência — o bot toma decisões, mas você sempre sabe o que vai acontecer antes de acontecer
PRINCÍPIO 03
Todo conteúdo externo é inspiração, não regra — expande o que já existe, nunca limita
Filtro de feature
Para cada ideia nova, perguntar: isso expande o que já existe? Se contradiz a ideia de crescimento contínuo ou tenta encolher o escopo antes da hora — identificar, sinalizar e rejeitar.
