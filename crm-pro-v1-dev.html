Fluxos

Como funciona

→
Autenticação Telegram OTP
1
Usuário solicita login: POST /auth/telegram/request com @username
2
Backend gera código de 6 dígitos, salva em crm_auth_codes (TTL 5 min) e envia via Telegram Bot
3
Usuário insere o código na tela de login: POST /auth/telegram/verify
4
Backend valida código, consulta session_version, gera JWT com payload completo (role, lojas, permissoes, exp às 19h BRT)
5
Frontend salva JWT em localStorage; RBAC aplicado automaticamente em todos os endpoints
→
Dashboard Executivo — Gestão
1
Usuário com role gestao acessa o Dashboard Comparativo
2
Frontend envia GET /api/stats/period com JWT; middleware requireGestao valida permissao ver_comparativo
3
Backend consulta tabela pedido_loja: receita, ticket médio e pedidos dos últimos 3 meses
4
GET /api/stats/period-by-loja retorna breakdown das 6 lojas lado a lado
5
Frontend renderiza tabela comparativa e gráfico de tendência em tempo real
→
Tratativa de Cliente — Vendedor
1
Vendedor abre perfil do cliente (filtrado automaticamente para sua loja)
2
Registra tratativa: POST /api/tratativas com resultado, canal e próximo follow-up
3
Backend faz INSERT em crm_tratativas + UPSERT em crm_overrides.timeline
4
Feed de Atividade Recente e Timeline Geral são atualizados em tempo real
5
Follow-up agendado aparece no Calendário do Vendedor no próximo acesso
Módulos

Componentes principais

Auth & RBAC
Autenticação sem senha via Telegram OTP + controle granular de acesso por role e permissões individuais
Login com @username Telegram → código OTP 6 dígitos TTL 5 min
JWT com expiração forçada às 19h BRT (sessão diária)
3 roles: gestao / admin / vendedor
5 permissões configuráveis por usuário no painel admin
Revogação de emergência via session_version (cache 60s)
Rate limit: 3 req/min por @username + 10/min por IP
POST /auth/telegram/verify { code: "482931" }
{ token: "eyJ...", user: { role: "gestao", permissoes: { ver_financeiro: true } } }
Dashboard & Analytics
Visão operacional e executiva da base de clientes com segmentação, inatividade e comparativo de receita por loja
7 segmentos: VIP / Em Risco / Perdido / Regular / Fiel / Novo / Lead
Inatividade: faixas 0-30 / 31-60 / 61-90 / 90+ dias
Dashboard Comparativo: receita 3 meses (gestao only)
Breakdown de receita por loja — 6 lojas lado a lado
Feed de atividade recente em tempo real
Follow-ups do dia integrados ao calendário
GET /api/stats/inatividade
{ d0_30: 6124, d31_60: 4751, d61_90: 3990, d90p: 36955 }
Gestão de Contatos
Lista, busca, filtros e edição de 51.820 clientes com bulk actions, paginação avançada e export CSV
51.820 clientes com histórico completo de pedidos
Bulk termômetro: classificação em massa até 500 clientes por chamada
Paginação avançada: ir para página X / primeiro / último (1.037 páginas)
Filtros por fase, termômetro, loja, inatividade
Export CSV restrito a admin e gestao
Gasto total visível apenas para gestao
PUT /api/clients/bulk-termometro { ids: [1..500], termometro: "Quente" }
{ updated: 500, timeline_synced: true }
Timeline & Follow-ups
Registro cronológico de todas as interações com clientes, agendamento de follow-ups e calendário da equipe
Feed cronológico de tratativas com autor, canal e resultado
Edições de fase e termômetro sobrescritas via crm_overrides
Calendário com follow-ups vencidos, do dia e futuros
UPSERT automático em crm_overrides.timeline após cada tratativa
Histórico CRM no modal de perfil do cliente
Formatação legível old→new, tags e notas (sem JSON cru)
POST /api/tratativas { cliente_id: 7821, resultado: "Interessado", followup: "2026-06-01" }
{ id: 9103, timeline_updated: true, feed_notified: true }
Painel Admin
Gerenciamento de usuários, permissões, suspensão e revogação de sessões em emergência
Criação de usuários com Telegram ID + role + lojas
Toggle de permissões granulares por usuário
Suspensão: POST /admin/users/:id/suspend (ativo=0)
Revogação de emergência: session_version++ → tokens invalidados em 60s
Filtro de loja: admin vê todas, vendedor apenas a própria
Auditoria de last_login e created_at por usuário
POST /admin/users/5/revoke
{ session_version: 3, tokens_invalidated_in: "60s", user: "@vendedor_x" }

O que guia cada decisão
